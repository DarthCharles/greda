# Use and customize a theme

Greda supplies a complete neutral base theme. Importing `styles.css` is enough
to use its components with the defaults. A custom theme, spacing rules, font
downloads, and Tailwind configuration are not required.

Use **Design Tokens** in the sidebar to explore the available tokens and their
visual results. The customization examples below are optional: override only
the CSS variables your application needs, and components and color utilities
automatically use those values.

## 1. Load the package stylesheet

Import the compiled stylesheet once in your application's entry point:

```tsx
// src/main.tsx
import "@darthcharles/greda/styles.css";

import { Button } from "@darthcharles/greda";
```

The package stylesheet already includes the base tokens. You do not need to
import `tokens.css` separately. It styles components without resetting your
application's page layout. Components continue to use normal package imports.

You can stop here and use the base theme. If you only need CSS variables without
component styles, import `@darthcharles/greda/tokens.css` instead.

## 2. Create the brand theme

To customize the base theme, create `src/comal-theme.css` and import it after
`@darthcharles/greda/styles.css` in your application entry point. Override only
the values your brand needs; the rest retain their base defaults. Define related
background and foreground colors together so labels remain readable.

This example takes Comal's warm canvas, paper surfaces, terracotta, and sage from
Meal Planner. It uses Meal Planner's darker terracotta for actions and a darker
muted text shade to improve contrast at small sizes.

```css
/* src/comal-theme.css */
[data-theme="comal"] {
  color-scheme: light;
  --background: 40 60% 96.078%; /* cream: #fbf7ef */
  --foreground: 37.5 10.256% 15.294%; /* ink: #2b2823 */
  --card: 42.857 100% 98.627%; /* paper: #fffdf8 */
  --card-foreground: 37.5 10.256% 15.294%;
  --popover: 42.857 100% 98.627%;
  --popover-foreground: 37.5 10.256% 15.294%;

  --primary: 9.5 55.556% 42.353%; /* dark terracotta: #a84330 */
  --primary-hover: 9.714 56.15% 36.667%;
  --primary-foreground: 0 0% 100%;
  --ring: 9.5 55.556% 42.353%;

  --secondary: 25.385 56.522% 90.98%;
  --secondary-foreground: 9.5 55.556% 42.353%;
  --accent: 85.714 29.167% 90.588%; /* soft sage: #e8eee0 */
  --accent-foreground: 37.5 10.256% 15.294%;
  --muted: 36.923 37.143% 93.137%;
  --muted-foreground: 41.25 7.273% 43.137%;
  --border: 38.824 27.869% 88.039%;
  --input: 38.824 27.869% 88.039%;

  --font-sans: "DM Sans Variable", "DM Sans", sans-serif;
  --font-heading: "Fraunces Variable", "Fraunces", serif;
  --radius: 0.75rem;
  --radius-sm: 0.375rem;
  --radius-lg: 1.5rem;
  --shadow: 0 16px 45px rgba(71, 49, 30, 0.08);
}
```

Colors accept **space-separated HSL channels**. For example, use
`--primary: 9.5 55.556% 42.353%`, rather than a hex value or a full `hsl()` call.
Typography, dimensions, and shadows accept ordinary CSS values. The overlay
color also includes an alpha channel, such as `37.5 10.256% 15.294% / 0.34`.

The complete working Comal example lives in `.storybook/themes/comal.css`.
It is a consumer example, excluded from the published package. Copy its overrides
into your application to start your theme.

## 3. Load your fonts and style the page

The default theme uses system fonts. The custom font imports and page rules in
this section are optional examples for the consuming application. Declaring a
font family does not download its font files. Storybook hosts DM Sans and Fraunces
locally using Fontsource. To use the same setup in an application:

```bash
npm install @fontsource-variable/dm-sans @fontsource-variable/fraunces
```

```tsx
// src/main.tsx, before your theme and app styles
import "@darthcharles/greda/styles.css";
import "@fontsource-variable/dm-sans";
import "@fontsource-variable/fraunces";
import "./comal-theme.css";
import "./app.css";
```

Apply your chosen canvas and typography to the application page:

```css
/* src/app.css */
body {
  margin: 0;
  background: hsl(var(--background));
  color: hsl(var(--foreground));
  font-family: var(--font-sans);
  line-height: var(--line-height);
}

h1,
h2,
h3 {
  font-family: var(--font-heading);
}
```

The package uses its heading token on component headings; your own page headings
need their own rule. The base theme never requires these external font packages.

## 4. Activate the theme at the document root

Set the attributes on `<html>`, rather than just the React application wrapper:

```html
<!-- index.html -->
<html lang="en" data-theme="comal" data-color-scheme="light">
  <!-- Your existing head and body -->
</html>
```

This lets dialogs, selects, tooltips, and other portaled content inherit the same
variables as your application. The initial HTML attributes also select the theme
before React mounts.

You can change the selection at runtime without replacing components:

```ts
function applyAppearance(theme: "base" | "comal", scheme: "light" | "dark") {
  document.documentElement.dataset.theme = theme;
  document.documentElement.dataset.colorScheme = scheme;
}

applyAppearance("comal", "light");
```

Using `base` removes Comal's selector match and restores the package defaults.
For an application with a single permanent brand, you can put the overrides in
`:root` instead and omit `data-theme`. Keep `data-color-scheme` if you offer dark mode.

## 5. Define the brand's dark palette

Brand and color scheme are independent. A base dark palette is available through
`data-color-scheme="dark"`. Because your brand selectors override those defaults,
provide matching dark overrides for the colors your brand sets.

Meal Planner currently defines a light theme only. Storybook's Comal dark option
is a complementary warm dark palette, rather than an existing Meal Planner theme.
For example:

```css
[data-theme="comal"][data-color-scheme="dark"] {
  color-scheme: dark;
  --background: 30 17.857% 10.98%;
  --foreground: 34.286 51.22% 91.961%;
  --card: 30 16.216% 14.51%;
  --card-foreground: 34.286 51.22% 91.961%;
  --popover: 30 16.216% 14.51%;
  --popover-foreground: 34.286 51.22% 91.961%;
  --primary: 15.625 75% 74.902%;
  --primary-hover: 15.789 77.551% 80.784%;
  --primary-foreground: 37.5 10.256% 15.294%;
  --ring: 15.625 75% 74.902%;
  --secondary: 22.5 24.49% 19.216%;
  --secondary-foreground: 17.015 70.526% 81.373%;
  --muted: 32.308 15.663% 16.275%;
  --muted-foreground: 33.103 19.205% 70.392%;
  --accent: 108 14.286% 20.588%;
  --accent-foreground: 102.857 28% 90.196%;
  --border: 30 15.476% 32.941%;
  --input: 30 15.476% 32.941%;
  --destructive: 7.174 79.31% 77.255%;
  --destructive-foreground: 37.5 10.256% 15.294%;
  --overlay: 30 20% 5% / 0.7;
}
```

You can initialize the scheme from `prefers-color-scheme` and persist a user's
choice in your application's settings. Set the resolved attribute before mounting
the UI so the correct palette is present on first render.

## 6. Adjust spacing and individual components

Spacing tokens are shared distances, not separate margin and padding settings.
For example, `--space-4` defaults to `1rem` (16px with a 16px root font size) and
can be used for padding, margin, gap, or a control dimension. The utility name or
CSS property determines how the distance is applied.

No spacing overrides or layout rules are required to use or theme Greda. To
customize the scale, override the base spacing unit on the document root, or a
named step for a more targeted change:

```css
:root {
  --spacing-unit: 0.25rem;
  --space-4: 1.25rem; /* Adjust the step used by p-4, px-4, and similar utilities. */
}
```

For your application's own layout, use any spacing token directly in CSS:

```css
/* Optional application layout example */
.section {
  display: grid;
  padding: var(--space-4);
  margin-bottom: var(--space-6);
  gap: var(--space-2);
}
```

This example styles an application element; it is not theme setup. In a Tailwind 4
app, the token import described below enables spacing utilities such as `p-4`,
`m-4`, and `gap-4`. If you use only Greda's precompiled stylesheet, spacing
classes are included only when used by a component; use CSS variables for any
additional layout needs.

Keep structural changes, such as a wider page layout, in application CSS. For a
single control, scope a token override using a consumer class:

```tsx
<Button className="compact-action">Save changes</Button>
```

```css
.compact-action {
  --radius: 0.375rem;
}
```

Use named spacing steps when adjusting a scoped section. Derived tokens such as
`--space-4` are computed where they are declared; changing `--spacing-unit` on a
nested wrapper alone will not recalculate inherited root declarations.

## Using Tailwind 4 in your application

Import Greda's tokens from the CSS file processed by your Tailwind build:

```css
/* src/app.css */
@import "tailwindcss";
@import "@darthcharles/greda/tokens.css";
```

That import includes the base palette, dark palette, and Tailwind theme
definitions. No preset, copied theme configuration, or app safelist is needed.
Tailwind generates utilities from the class names in your application source:

```tsx
<section className="grid gap-4 rounded-md bg-primary p-4 text-primary-foreground md:p-8 hover:bg-primary/90">
  Application content
</section>
```

The integration maps semantic colors, spacing, font families, font sizes,
weights, radii, shadows, and the dialog width to Greda's runtime tokens. Named
spacing steps such as `p-4`, `m-4`, and `gap-4` share `--space-4`; other numeric
steps derive from `--spacing-unit`. Fractional utilities such as `p-0.5` use
`--space-0-5`. It also provides the token-based border width, `ring-1`, `ring-2`,
`ring-offset-2`, `opacity-disabled`, and the named stacking utilities `z-overlay`,
`z-popover`, and `z-toast`.

Color utilities support Tailwind's normal opacity and state variants. The
`dark:` variant follows `data-color-scheme="dark"`, matching Greda's palette.
Changing a token updates both application utilities and Greda components;
customization is optional and requires no rebuild of the library.

### Using components and your own Tailwind utilities together

Import the compiled component styles into the `components` layer before the
token import:

```css
@import "tailwindcss";
@import "@darthcharles/greda/styles.css" layer(components);
@import "@darthcharles/greda/tokens.css";
```

Import this app stylesheet once at your application entry point. Do not also
import Greda's `styles.css` in JavaScript: an unlayered duplicate would take
precedence over the app's layered Tailwind utilities. This setup lets application
classes, including responsive and opacity variants, override component defaults:

```tsx
<Button className="md:bg-secondary md:text-secondary-foreground">
  Responsive action
</Button>
```

The Tailwind theme definitions are registered at build time, so a JavaScript
import of `tokens.css` alone cannot register utilities. Plain CSS consumers can
still import the same file for its runtime variables; browsers ignore the
Tailwind directives. This CSS-only integration targets Tailwind 4. Tailwind 3
consumers can use the precompiled component styles but must configure their own
Tailwind theme to generate additional token-based utilities.

## Shared utilities without an application Tailwind build

Greda components and consuming applications use the same unprefixed Tailwind
class names and CSS variables. Import `styles.css` once; no separate utility
stylesheet or Tailwind setup is required:

```tsx
<div className="comal-ui border border-primary bg-accent p-4 text-accent-foreground">
  Application content
</div>

<Button className="bg-secondary text-secondary-foreground hover:bg-accent hover:text-accent-foreground">
  Custom action
</Button>
```

The package guarantees `bg-{color}`, `text-{color}`, and `border-{color}` for
every semantic color in the token catalog, including `primary`, `foreground`,
`accent`, `card-foreground`, and `border`. The `hover:`, `focus:`, and
`focus-visible:` variants of these color utilities are also included. Colors
follow the active theme and color scheme, including custom token overrides.

Components already apply `comal-ui`. Add it to standalone elements when you need
Greda's scoped baseline, including solid borders and Tailwind variable
initialization. Color utilities also work on elements without `comal-ui`.
Other layout utilities and opacity, responsive, or state combinations are
included only when used by a component. These limits apply to the precompiled
stylesheet; apps importing the Tailwind 4 token theme generate their own utilities
from their source and can use any supported combination.

The exported `cn` helper merges unprefixed utilities. A consumer `className`
replaces conflicting component defaults for the same state:

```tsx
import { cn } from "@darthcharles/greda";

cn("bg-primary hover:bg-primary-hover", "bg-accent hover:bg-secondary");
// "bg-accent hover:bg-secondary"
```

Utility selectors are global. Use the layered setup above for Tailwind 4 so both
builds share the same mapping and app utilities can override component styles.
Tailwind 3 requires manual theme mappings (for example, `primary` to
`hsl(var(--primary) / <alpha-value>)`). Matching class names share the cascade,
so align any app theme customizations with Greda's variables. The package's reset
and Tailwind variable defaults remain scoped; its CSS does not add global preflight.

### Migrating from prefixed utilities

This is a breaking class-name change. Remove `ds-` from consumer classes and CSS
selectors, including utilities after state modifiers. For example:

```text
ds-bg-primary              → bg-primary
hover:ds-bg-primary-hover  → hover:bg-primary-hover
-ds-mx-1                   → -mx-1
```

Update escaped CSS selectors and any app Tailwind configuration that used the old
prefix. Old `ds-*` classes are no longer generated or merged by `cn`. Token names,
value formats, component props, and package imports remain the same.

## Scoped previews and portals

A document-wide theme is the easiest setup for an application. If you need a
separate theme inside one subtree, set both attributes on that container and pass
its element to the relevant content component's `container` prop. This keeps
portaled content inside the themed subtree:

```tsx
const [container, setContainer] = useState<HTMLDivElement | null>(null);

return (
  <div ref={setContainer} data-theme="comal" data-color-scheme="light">
    <Dialog>
      <DialogTrigger asChild>
        <Button>Edit profile</Button>
      </DialogTrigger>
      <DialogContent container={container}>
        <DialogTitle>Edit profile</DialogTitle>
        <DialogDescription>Update your public information.</DialogDescription>
      </DialogContent>
    </Dialog>
  </div>
);
```

`DialogContent`, `SelectContent`, and `TooltipContent` support this container prop.
Test hover, focus, invalid, disabled, and loading states in both palettes. Use the
Storybook **base / comal** and **light / dark** toolbar options to review the same
components and visual tokens under each theme.
