# Matrix

Matrix is technical, high-contrast, and deliberately spare. Phosphor-green
actions sit against green-black surfaces in dark mode; light mode pairs pale
greens with deeper green actions. System monospace type, tight display tracking,
fine borders, and square controls reinforce its terminal character. Keep status
labels explicit so color supports meaning without carrying it alone.

Choose **matrix** and **light / dark** in the toolbar to preview the theme.

## Install the theme and fonts

Components work with Greda's compiled package CSS, without Tailwind:

```tsx
import "@darthcharles/greda/styles.css";
import "@darthcharles/greda/themes/matrix.css";
```

Set the theme and scheme on the same boundary:

```html
<html data-theme="matrix" data-color-scheme="dark">
```

Importing the theme alone leaves the neutral base unchanged. Switch the scheme
to explore the complementary palette. Your application controls its page shell:

```tsx
<body className="m-0 surface-primary font-sans text-primary">
  {/* Your application */}
</body>
```

The theme uses installed system fonts and downloads nothing. Override
`--font-sans` and `--font-heading` to use your own families.

## Compose the page

The recipe uses Tailwind layout utilities. With Tailwind 4 configured, use these
imports in your application CSS entry point instead of the JavaScript CSS imports:

```css
@import "tailwindcss";
@import "@darthcharles/greda/styles.css" layer(components);
@import "@darthcharles/greda/tokens.css";
@import "@darthcharles/greda/themes/matrix.css";
```

Import that entry point once. Your application Tailwind build must scan the copied
JSX; recipe-only layout classes are not included in Greda's compiled CSS. The
components layer lets application utilities override component defaults.
Tailwind 3 consumers need corresponding token mappings in their configuration.

Button, Badge, Tabs, Input, Label, and Select come from `@darthcharles/greda`.
The console opens on its log. A Settings tab reveals a session-name field and
an output selector, keeping these controls within the console context. Shared typography roles
supply the monospace scale; terminal borders, the decorative prompt, and log
layout stay local to the recipe. The initialization log is static fictional
content. No shell commands run, and there are no network requests, authentication,
or saved sessions.

## Responsive layout and interaction

The introduction stacks below the medium breakpoint; protocol details stack
below the small breakpoint. Header and footer content wrap on narrow screens.
Status text accompanies color, and decorative terminal symbols are hidden from
assistive technology.

Tab focuses “Explore the protocol”; Enter moves focus to the protocol with a
visible outline. Button retains anchor semantics through `asChild`; its loading
and disabled props do not guarantee a disabled link. The cursor and log stay
still, including with reduced motion. Arrow keys switch between Log and Settings;
the settings fields are editable local examples and run no commands. See individual component stories for
disabled, loading, and validation states.

## Scoped themes

Put `data-theme="matrix"` and `data-color-scheme="light"` or `"dark"` on the
same wrapper. Apply surface, text, and font styles through the shared roles.
For portaled DialogContent, SelectContent, and TooltipContent, pass an element
inside that wrapper as `container` so the portal inherits the theme. A document
theme naturally reaches portals mounted under body.

Keep the theme's low-specificity selectors. Override base colors, typography,
and shape tokens after importing the theme to customize the result. The theme
provides variables; the consuming application controls page composition.
